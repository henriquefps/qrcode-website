# Deploy

Qrcode is a single Cloudflare Worker named `qrcode`: static assets (the Vite client build, SPA fallback to `index.html`) plus a tiny entrypoint, `worker/index.ts` (only `export default`; workerd rejects other named exports). Config lives in `cloudflare.config.ts` (the `cf` CLI; there is no Wrangler config).

- `qrcode.hfps.dev` → the app (assets).
- `qrgo.hfps.dev` → the Worker answers `/sw.js` with a self-unregistering service worker (drops old Qrgo PWA caches and sends open windows to https://qrcode.hfps.dev) and 301-redirects every other path to `https://qrcode.hfps.dev<path+query>`.

`runWorkerFirst: true` is required because assets patterns can't filter by host, so the Worker sees every request and passes non-qrgo hosts to `env.ASSETS`.

## Commands

`cf` needs Node >= 22.18 and does not run under Bun; the scripts call it with `node`. Bun stays for install/build/test.

```sh
bun run build       # vite build; writes assets + worker to .cloudflare/output/v0/ (gitignored)
bun run deploy:dry  # build + `cf deploy --dry-run` (no upload, no DNS)
bun run deploy      # build + `cf deploy` (publishes the Worker and both custom domains)
bun run test        # includes worker routing tests (worker/routing.test.ts)
```

## PWA plugin note

The Vite config uses `@cloudflare/vite-plugin`, which writes client assets into cf's Build Output, not `dist/`. When `vite-plugin-pwa` is added, set its `outDir` to `.cloudflare/output/v0/workers/default/assets` (as in Designer) so `sw.js` and the precache manifest land in the deployed assets.

Caching: `public/_headers` serves `sw.js`, `registerSW.js`, `index.html`, `/` and `manifest.webmanifest` with `no-cache`, and `/assets/*` as immutable.

## Security headers

`public/_headers` also sends these on every path (`/*`); the assets binding applies them to everything the Worker passes through to `env.ASSETS` (the qrgo redirect and self-unregistering `sw.js` are generated by the Worker and carry none).

| Header | Value | Why |
| --- | --- | --- |
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self' data: blob:; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; media-src 'self' blob:; worker-src 'self' blob:; manifest-src 'self'; font-src 'self' data:; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'` | Nothing is loaded from or sent to another origin. `'wasm-unsafe-eval'` is for the zxing WASM decoder (the `.wasm` is bundled, not fetched from a CDN). `blob:`/`data:` cover the camera stream, QR previews, downloads and logos (qr-code-styling `fetch`es logo data URIs, so `connect-src` allows `data:` and `blob:`, which never touch the network). `'unsafe-inline'` is for styles only (Sonner and Radix inject `<style>`/style attributes); there is no inline script, and the JSON-LD block is `type="application/ld+json"` data that CSP does not execute. |
| `Permissions-Policy` | `camera=(self), display-capture=(self), microphone=(), geolocation=(), payment=(), usb=(), serial=(), bluetooth=(), hid=(), midi=(), accelerometer=(), gyroscope=(), magnetometer=(), clipboard-read=(), interest-cohort=()` | Only the camera and screen capture (for reading a QR on screen) are allowed, and only for our own origin. Anything else the app does not need is off. |
| `Referrer-Policy` | `no-referrer` | Links out never reveal the page. |
| `X-Content-Type-Options` | `nosniff` | No MIME sniffing. |
| `Cross-Origin-Opener-Policy` | `same-origin` | Isolates the browsing context from cross-origin windows. |

If a feature needs a new origin, API or inline script, change the CSP in `_headers` deliberately; do not loosen it with wildcards. Test the production build (not `bun run dev`) since only it is served with these headers.

## CI and dependency updates

`.github/workflows/ci.yml` runs on pull requests and pushes to `main`: `bun install --frozen-lockfile`, lint, `tsc -b`, tests and build. It never deploys. `.github/dependabot.yml` opens weekly grouped PRs for npm (minor and patch together) and GitHub Actions.

## Manual step before the first deploy: free `qrgo.hfps.dev`

`qrgo.hfps.dev` is currently attached to the Pages project `qrgo`, with a DNS CNAME `qrgo.hfps.dev` → `qrgo-1d3.pages.dev`. A hostname can have only one owner, so before the deploy:

1. Remove the DNS CNAME `qrgo.hfps.dev` → `qrgo-1d3.pages.dev` (the Worker custom-domain attach needs the name free).
2. Detach the domain from Pages (this takes qrgo.hfps.dev offline until the Worker deploys, so deploy right after):

```sh
cf pages domains delete qrgo.hfps.dev --project-name qrgo --dry-run   # preview only
cf pages domains delete qrgo.hfps.dev --project-name qrgo             # asks for confirmation
```

3. `bun run deploy`. The Pages project itself can stay.
